# Suora MCP 深度迭代手册（30 个落地点）

这份手册把 `MCP` 模块收敛成 30 个真实落地点，重点是服务接入、作用域、传输方式、安全边界和排障路径。

## 1. 基础认知

1. MCP 是外部能力接入层，不是普通设置附页。
2. 先区分 workspace scope 和 user scope。
3. 先区分 `stdio` 和网络型 transport。
4. 先区分服务不可达和 Agent 不可见两类问题。
5. 不要把 Skill 和 MCP 混为一谈。

## 2. 传输方式

6. `stdio` 适合本机命令驱动服务。
7. `http` 适合稳定请求-响应服务。
8. `sse` 适合事件流场景。
9. `ws` 适合长连接交互场景。
10. transport 选择应由服务本身决定，而不是偏好决定。

## 3. 配置要素

11. URL、命令、args、env、headers 都应最小化配置。
12. env 应只注入服务真正需要的变量。
13. headers 应只保留必要认证信息。
14. user scope 只给真正跨工作区共享的服务。
15. workspace scope 适合项目专属工具链。

## 4. 使用与排障

16. 保存后先测试连接，不要直接回 Chat 试错。
17. 连接成功后再回 Agent 检查能力是否可见。
18. Agent 看不到能力时，先查状态，再查权限。
19. URL 看起来对但连不上时，优先查协议和网络可达性。
20. `stdio` 连不上时，优先查命令、cwd 和环境变量。

## 5. 风险与安全

21. 高权限 MCP 服务应只给窄权限 Agent 使用。
22. user scope 服务出错会影响更多工作区。
23. 生产系统类 MCP 服务应有单独审查。
24. 不可信第三方 MCP 服务不要直接接入核心工作流。
25. 敏感认证头不应扩散到其他文档或技能中。

## 6. 治理与维护

26. 服务长期失效应停用或清理。
27. 作用域变化时应重新审查边界。
28. 同类能力过多时应合并或分层管理。
29. 关键服务应保留验证方法和依赖说明。
30. 好的 MCP 治理最终目标是连接可靠、作用域清楚、权限受控、能力可验证。
