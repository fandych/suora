# Suora 模块用户手册（10 模块，10 轮，30 问）

阅读方法：每个模块固定拆成 10 轮；每轮 3 个问题。你不需要一次读完，只需要在当前任务卡住时跳到对应问题。

## 1. Chat

如果你要看超细版样板，请继续阅读 [docs/user/CHAT_DEEP_DIVE_ZH.md](../user/CHAT_DEEP_DIVE_ZH.md)。这份扩展文档把 Chat 单独展开成 10 轮、每轮 30 问的深挖手册。

### 第 1 轮：定位与入口
1. Chat 解决什么问题？答：它是日常对话、任务执行、工具调用和流水线命令的主入口。
2. 什么时候先打开 Chat？答：当模型和 Agent 已经可用，且你准备开始一轮实际任务时。
3. 进入 Chat 前至少要准备什么？答：至少一个已配置 provider、一个已启用模型，最好再选好默认 Agent。

### 第 2 轮：首次配置
4. 第一眼先看哪里？答：先看会话列表，再看当前会话顶部的模型和 Agent 选择器。
5. 第一次发送消息前要做什么？答：确认当前会话绑定的是你真正想用的模型和 Agent。
6. 如果什么都没配会怎样？答：你仍能进入页面，但真正的 AI 回复会因缺少模型而不可用或失败。

### 第 3 轮：核心对象
7. Chat 里最核心的数据对象是什么？答：会话、消息、附件、当前 Agent、当前模型。
8. 会话和消息的关系是什么？答：一个会话承载一串持久化消息，后续追问、编辑和重试都围绕它进行。
9. Agent 和模型分别控制什么？答：Agent 定角色和工具边界，模型定推理能力、速度和成本。

### 第 4 轮：标准流程
10. 一次标准对话怎么走？答：选会话、选 Agent、选模型、发消息、观察流式回复和工具事件、继续追问。
11. 上传附件时应该注意什么？答：先确认模型支持对应输入，再在提示里明确你要模型如何处理附件。
12. 回复失败后先做什么？答：先看是否是 provider 连接、限流、工具权限或上下文本身的问题，再考虑重试。

### 第 5 轮：协作链路
13. Chat 最常和哪个模块联动？答：最常和 Models、Agents、Documents、Pipeline 联动。
14. 什么时候要回到 Documents？答：当问题依赖长期资料，而不是一次性输入时。
15. 什么时候要回到 Agents？答：当你发现回复风格、工具权限或角色分工不合适时。

### 第 6 轮：进阶能力
16. Chat 里除了普通问答还能做什么？答：可以查看工具调用、分支对话、编辑消息、重试回复、朗读文本和触发 `/pipeline` 命令。
17. `/pipeline` 什么时候值得用？答：当你已经把重复流程保存成流水线，想在对话里直接列出、运行或查看状态时。
18. 什么情况下不该继续堆上下文？答：当会话已经偏题、输入过杂或你需要换角色时，应该新建会话或分支。

### 第 7 轮：结果判断
19. 什么算一次成功的 Chat 任务？答：结果正确、引用上下文清楚、工具执行可解释，而且后续动作明确。
20. 什么算只是“模型说了很多”但没有完成？答：输出缺少结构、没有回答目标、没有落到下一步行动。
21. 如何快速判断该不该保留当前会话？答：如果这条线程还会继续演化就保留，否则另开新会话更干净。

### 第 8 轮：常见故障
22. 看不到回复通常先查什么？答：先查 provider 是否可连、模型是否启用、当前会话是否真的发送成功。
23. 工具调用异常通常先查什么？答：先查 Agent 的工具权限和 `Settings -> Security` 的确认或阻断策略。
24. 附件效果差通常是什么原因？答：常见原因是模型不支持该模态，或你的提示没有明确处理目标。

### 第 9 轮：安全边界
25. Chat 里最该谨慎的是什么？答：敏感附件、危险命令和需要工具执行的高风险任务。
26. 为什么同一个问题在不同 Agent 下风险不同？答：因为 Agent 的允许工具、禁止工具和权限模式并不相同。
27. Secure Storage 警告和 Chat 有什么关系？答：它直接影响模型密钥是否能跨重启保留。

### 第 10 轮：维护与迭代
28. Chat 用久了怎么整理？答：把长期价值高的内容转入 Documents，把稳定流程沉淀为 Pipeline。
29. 什么时候应该新建一个专业 Agent？答：当同类任务反复出现，且通用 Assistant 总要被你反复纠正时。
30. 下一轮优化 Chat 的优先级是什么？答：先优化模型选择和 Agent 选择，再优化上下文和工具策略。

## 2. Documents

如果你要看超细版样板，请继续阅读 [docs/user/DOCUMENTS_DEEP_DIVE_ZH.md](../user/DOCUMENTS_DEEP_DIVE_ZH.md)。这份扩展文档把 Documents 单独展开成 10 轮、每轮 30 问的深挖手册。

### 第 1 轮：定位与入口
1. Documents 解决什么问题？答：它负责本地知识沉淀、文档组织、回链分析和图谱浏览。
2. 什么时候先打开 Documents？答：当任务依赖长期资料，而不是一次性的聊天上下文时。
3. 进入前最少需要什么？答：只需要一个工作区思路；不必先有模型也能开始整理知识。

### 第 2 轮：首次配置
4. 第一次应该先建什么？答：先建文档组，再在组里建文件夹和文档。
5. 为什么先建文档组而不是直接写文档？答：因为组是长期知识区的边界，后续搜索、图谱和上下文都更清晰。
6. 一个组里文档太多会怎样？答：可维护性会迅速下降，回链和图谱也更难读。

### 第 3 轮：核心对象
7. Documents 的核心对象有哪些？答：文档组、文件夹、文档节点和文档正文。
8. 回链和引用的价值是什么？答：它们让你看到一份笔记被谁引用、缺了什么连接、哪些内容是孤岛。
9. 图谱不是装饰吗？答：不是，它是发现桥接节点、稀疏簇和知识缺口的观察面。

### 第 4 轮：标准流程
10. 标准写作流程怎么走？答：选组、选目录、新建 Markdown 文档、编辑、保存、检查回链和搜索结果。
11. 什么时候用 Mermaid？答：当你要表达流程、结构、依赖或系统关系时。
12. 什么时候用数学公式？答：当文档内容包含推导、统计表达或需要精确符号时。

### 第 5 轮：协作链路
13. Documents 最常和哪个模块一起用？答：最常和 Chat 一起用。
14. 为什么不把长期资料都直接塞进 Chat？答：因为聊天上下文会变，而文档需要稳定结构、保存和可回查关系。
15. 什么时候和 Agents 联动？答：当你希望 Document editor 或其他 Agent 直接帮你整理、改写或生成文档时。

### 第 6 轮：进阶能力
16. Documents 的进阶价值是什么？答：不是“能写 Markdown”，而是能把知识变成可搜索、可回链、可观察的本地资产。
17. 什么时候看图谱最有价值？答：当你已经写出一批文档，想发现断裂关系和意外连接时。
18. 健康分析适合什么时候看？答：适合在资料越来越多、你开始怀疑知识结构是否失衡时看。

### 第 7 轮：结果判断
19. 什么算一个健康的文档区？答：主题边界清楚、目录稳定、文档可搜索、关键主题有回链而不是孤立散落。
20. 什么算文档写多了但没积累价值？答：内容重复、命名混乱、没有链接、回头自己都找不到。
21. 什么时候该拆新文档组？答：当主题、受众或工作域已经明显和原来的知识区不同。

### 第 8 轮：常见故障
22. 搜索效果不好通常先查什么？答：先查命名、标题、关键词是否稳定，再查文档是否真正保存。
23. 图谱看不出价值通常为什么？答：通常是链接习惯太弱，文档之间没有显式关系。
24. 导入后结构混乱怎么办？答：先整理组和文件夹，再统一命名，再补关键回链。

### 第 9 轮：安全边界
25. Documents 里最该谨慎的是什么？答：包含敏感资料的导入、导出和被 Chat 引用的内容边界。
26. 为什么文档上下文要有选择地带入 Chat？答：因为无差别注入会抬高成本，也可能把无关敏感信息带进去。
27. 本地优先意味着什么？答：意味着你的知识资产优先保存在本地工作台，而不是默认依赖远端系统。

### 第 10 轮：维护与迭代
28. 文档区怎么定期维护？答：定期清理重复文档、补关键回链、把热点主题拆成稳定目录。
29. 什么时候把文档流程交给 Agent？答：当你已经有固定写作规范，希望 AI 只负责落地和改写时。
30. 下一轮优化 Documents 的优先级是什么？答：先优化结构和命名，再优化图谱关系，最后再扩展自动化。

## 3. Pipeline

如果你要看超细版样板，请继续阅读 [docs/user/PIPELINE_DEEP_DIVE_ZH.md](../user/PIPELINE_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Pipeline 解决什么问题？答：它把多步 Agent 任务保存成可重复执行的流程。
2. 什么时候先打开 Pipeline？答：当同类任务你已经手工做了两三次以上，而且步骤大体稳定时。
3. 进入前最好先准备什么？答：准备好可用 Agent、目标模型和一条你愿意标准化的任务路径。

### 第 2 轮：首次配置
4. 第一次建流水线时先做什么？答：先写清楚目标产出，再拆步骤，而不是先堆很多参数。
5. 第一个版本应复杂吗？答：不应，先做最短可运行流程，再逐步加条件、预算和重试。
6. 为什么不要一上来建超长流程？答：因为越长越难定位失败点，调试成本会迅速升高。

### 第 3 轮：核心对象
7. Pipeline 的核心对象是什么？答：保存的流水线、步骤、变量、预算、执行历史。
8. `runIf` 是做什么的？答：它决定某一步在什么条件下运行或跳过。
9. 预算的意义是什么？答：控制总时长、总 token 或最大步骤数，避免成本和执行时间失控。

### 第 4 轮：标准流程
10. 一次标准建流过程怎么走？答：命名、写说明、加步骤、给步骤选 Agent、设置变量与条件、试运行、看历史。
11. Dry run 有什么价值？答：先检查结构、变量和条件，减少真跑时才暴露的问题。
12. 真跑后最应该看哪里？答：先看步骤状态、输出、错误，再看执行引擎标签和 fallback 原因。

### 第 5 轮：协作链路
13. Pipeline 常和哪些模块协作？答：最常和 Agents、Chat、Timer 协作。
14. 什么时候从 Chat 跳到 Pipeline？答：当一次对话已经暴露出稳定的多步模式时。
15. 什么时候再加 Timer？答：当这条流程不只要复用，还要按时间自动触发时。

### 第 6 轮：进阶能力
16. 流水线最有价值的进阶能力是什么？答：变量传递、条件执行、预算限制和执行历史。
17. Mermaid 预览有什么意义？答：它让你先看流程结构是否合理，再决定是否运行。
18. 什么情况下需要重试和退避？答：涉及网络调用、外部工具或易抖动 provider 时。

### 第 7 轮：结果判断
19. 什么算一个好流水线？答：步骤边界清楚、输入输出可追踪、失败可定位、运行成本可控。
20. 什么算“看起来很强但不适合长期用”？答：流程太长、提示太耦合、历史难读、每次都要人工救火。
21. 什么时候该拆成两条流水线？答：当一条流程里混了不同目标或不同触发场景。

### 第 8 轮：常见故障
22. 流水线失败先查哪里？答：先查该步骤的 Agent、输入、变量引用和工具权限。
23. 看到 fallback 警告代表什么？答：代表当前运行已从 workflow 路径降级到 legacy 路径或其他安全回退。
24. 跳步不符合预期通常是什么原因？答：通常是 `runIf` 条件、变量值或步骤启用状态不对。

### 第 9 轮：安全边界
25. Pipeline 最大的风险点是什么？答：多步任务里把高风险工具、外部平台和敏感内容串起来后放大了影响面。
26. 为什么步骤要尽量单一职责？答：这样失败时才知道是哪个环节出错，也更容易收紧权限。
27. 什么时候要先回到 Settings 或 Agents？答：当问题根源其实是工具权限、provider 配置或 Agent 策略，而不是流程结构。

### 第 10 轮：维护与迭代
28. 流水线多久该复盘一次？答：当历史里开始出现重复错误、成本异常或人工介入过多时。
29. 什么时候应该导出备份？答：在你准备大改步骤结构、变量或预算前。
30. 下一轮优化优先级是什么？答：先缩短路径，再稳住输入输出，最后才扩展更复杂分支。

## 4. Models

如果你要看超细版样板，请继续阅读 [docs/user/MODELS_DEEP_DIVE_ZH.md](../user/MODELS_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Models 解决什么问题？答：它负责 provider 配置、模型启用、连接测试和模型比较。
2. 什么时候先打开 Models？答：任何 AI 能力用不了时，第一站都应该先到这里。
3. 进入前需要准备什么？答：准备好 API Key、本地地址或私有网关信息。

### 第 2 轮：首次配置
4. 第一次要先点哪个子视图？答：先去 `Providers`。
5. 配完 provider 还不够吗？答：还不够，你还要去 `Models` 子视图启用具体模型。
6. 为什么要先测连接？答：这样能先把凭据、Base URL 和模型 ID 问题暴露出来。

### 第 3 轮：核心对象
7. Models 里的核心对象有哪些？答：provider 配置、provider 下的模型列表、启用状态、模型参数。
8. provider 和 model 的关系是什么？答：provider 是连接入口，model 是真正被 Chat、Agent 和 Pipeline 调用的能力单元。
9. Compare 子视图的价值是什么？答：帮助你在真实工作前比较速度、质量和稳定性。

### 第 4 轮：标准流程
10. 标准配置流程怎么走？答：建 provider、填 key 和 base URL、保存、测试连接、启用模型、回到其他模块使用。
11. Ollama 和云端 provider 的差异是什么？答：Ollama 通常走本地地址，不依赖云 API Key。
12. OpenAI-compatible 适合什么场景？答：适合私有网关、自建代理或兼容 OpenAI 协议的模型平台。

### 第 5 轮：协作链路
13. Models 最常服务哪些模块？答：Chat、Agents、Pipeline、Timer、Channels。
14. 为什么 Agent 调不好时也要回来看 Models？答：因为很多“Agent 表现问题”其实是模型选错或模型没启用。
15. Compare 的结果会影响什么？答：会影响默认模型、特定 Agent 绑定和流水线成本设计。

### 第 6 轮：进阶能力
16. Models 的进阶价值是什么？答：在同一工作台里并行管理云端、本地和兼容网关模型。
17. 为什么 UI 支持和运行时支持要分开理解？答：因为运行时支持的 provider 比当前编辑器显式暴露的类型更广。
18. 什么时候该保留多个 provider？答：当你要平衡成本、速度、上下文长度和可用性时。

### 第 7 轮：结果判断
19. 什么算模型配置完成？答：provider 可连、至少一个模型已启用，而且你能在 Chat 成功发起对话。
20. 什么算只是“填了配置”但还没真正可用？答：模型未启用、没做连接测试或没有被其他模块选中。
21. 什么时候该下线一个模型？答：当它长期失效、成本不合理或已被更稳定方案替代时。

### 第 8 轮：常见故障
22. 连接失败先查什么？答：先查 API Key、Base URL、模型 ID 和网络代理。
23. 看不到模型通常是什么原因？答：通常是 provider 下模型没同步或没启用。
24. 明明 provider 保存了但 Chat 仍不可用怎么办？答：回到 `Models -> Models` 检查启用状态，再回 Chat 重新选择。

### 第 9 轮：安全边界
25. Models 最大的敏感数据是什么？答：API Key 和私有网关地址。
26. 为什么 Secure Storage 警告要认真看？答：因为这决定密钥是否能安全持久化，还是只在内存中暂存。
27. Base URL 乱填会有什么问题？答：可能导致调用错误、请求发错环境，甚至把敏感请求打到不可信服务。

### 第 10 轮：维护与迭代
28. 模型配置多久该复盘？答：当 provider 变多、成本上升或质量开始不稳定时。
29. 如何降低模型列表混乱？答：只启用你真正会在工作流里使用的模型。
30. 下一轮优化优先级是什么？答：先稳定 provider，再精简模型，再做针对任务的模型比较。

## 5. Agents

如果你要看超细版样板，请继续阅读 [docs/user/AGENTS_DEEP_DIVE_ZH.md](../user/AGENTS_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Agents 解决什么问题？答：它把角色、提示词、模型、技能、工具权限和行为参数绑定成可复用执行单元。
2. 什么时候先打开 Agents？答：当你发现同一类任务总要反复解释角色、格式和边界时。
3. 进入前最好具备什么？答：至少一个可用模型，以及你对任务目标的基本角色设想。

### 第 2 轮：首次配置
4. 第一次进来先做什么？答：先浏览默认 Agent，理解哪些是通用型、哪些是构建器、哪些是专业型。
5. 应该直接新建 Agent 吗？答：不一定，很多时候从复制现有 Agent 开始更稳。
6. 一个可用 Agent 最少要哪些字段？答：名称、系统提示词、模型偏好和启用状态。

### 第 3 轮：核心对象
7. Agent 的核心配置有哪些？答：提示词、模型、技能、温度、token 上限、最大轮次、工具白名单/黑名单、权限模式、记忆。
8. 技能和 Agent 的关系是什么？答：技能补充领域规则与资源，Agent 决定是否使用这些能力。
9. 为什么 Agent 不是提示词模板？答：因为它还携带工具边界、行为参数、记忆和运行策略。

### 第 4 轮：标准流程
10. 创建自定义 Agent 的标准流程是什么？答：复制或新建、命名、写系统提示词、选模型、绑技能、调参数、设工具权限、测试、保存。
11. 页面内测试有什么意义？答：它能在不污染正式会话的前提下先验证角色是否成立。
12. 什么时候该做版本快照？答：任何一次大改提示词、工具权限或技能绑定之前。

### 第 5 轮：协作链路
13. Agents 最常和哪些模块协作？答：几乎所有 AI 模块都会用到它，尤其是 Chat、Pipeline、Timer、Channels。
14. 什么时候该从 Chat 回到 Agents？答：当你不是“问题问错了”，而是“角色本身不对”时。
15. Skills 在这里起什么作用？答：它们让 Agent 在特定领域里更稳定、更像一套可复用能力。

### 第 6 轮：进阶能力
16. 内置构建器 Agent 的价值是什么？答：它们帮助你在对应模块里创建 Agent、Pipeline、Timer 或 Channel 配置，而不是直接替你做业务任务。
17. 记忆适合什么时候打开？答：当同一 Agent 需要跨多轮或长期任务保留偏好与经验时。
18. 什么时候需要工具白名单/黑名单？答：当你要显式限制风险面，或确保专业 Agent 不乱用不相关工具时。

### 第 7 轮：结果判断
19. 什么算一个好 Agent？答：角色清楚、输出稳定、权限收敛、换任务时边界明确。
20. 什么算 Agent 过拟合？答：只有在极窄提示下表现好，一换场景就崩或开始胡乱调用工具。
21. 什么时候该拆成两个 Agent？答：当一个 Agent 同时承担两种风格冲突或权限冲突的职责。

### 第 8 轮：常见故障
22. Agent 效果差先查什么？答：先查模型绑定、系统提示词和技能绑定，再查温度与工具权限。
23. Agent 不执行工具通常为什么？答：可能是权限模式、工具限制、模型能力或任务提示不清。
24. 导入后 Agent 不好用怎么办？答：先本地测试，再统一模型、技能和权限策略，不要直接丢进生产流程。

### 第 9 轮：安全边界
25. Agent 最大的风险是什么？答：把过宽工具权限和模糊提示词组合在一起。
26. 为什么专业 Agent 通常比通用 Agent 更安全？答：因为职责越窄，权限和输出边界越容易收紧。
27. 哪类 Agent 最该谨慎对外使用？答：绑定 Channels、Timer 或高风险工具的自动执行型 Agent。

### 第 10 轮：维护与迭代
28. Agent 如何长期维护？答：保留版本快照、定期清理提示词冗余、复盘失败案例。
29. 什么时候该废弃一个 Agent？答：当它职责重叠、维护成本过高或已被更清晰的新 Agent 替代。
30. 下一轮优化优先级是什么？答：先改系统提示词，再改模型绑定，再改技能和工具策略。

## 6. Skills

如果你要看超细版样板，请继续阅读 [docs/user/SKILLS_DEEP_DIVE_ZH.md](../user/SKILLS_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Skills 解决什么问题？答：它把可复用的领域规则、流程说明和资源打包成 `SKILL.md` 能力包。
2. 什么时候先打开 Skills？答：当你想让多个 Agent 共享同一套领域约束，而不是重复复制提示词时。
3. 进入前最好先知道什么？答：技能不是底层工具注册表，而是提示词和资源层的能力包。

### 第 2 轮：首次配置
4. 第一次进来先看什么？答：先看已安装技能和来源过滤。
5. 应该先安装还是先编辑？答：如果已有现成技能先安装，没有再新建或导入。
6. 什么时候要配置外部目录？答：当你有团队共享技能库或想接入其他 agent 目录时。

### 第 3 轮：核心对象
7. Skills 的核心对象有哪些？答：技能元数据、`SKILL.md` 正文、资源树、来源和启用状态。
8. 来源为什么重要？答：因为本地、项目、用户、注册表、共享目录的管理方式不同。
9. 资源树解决什么问题？答：让技能不只是几段文字，还能带模板、脚本、说明和参考资产。

### 第 4 轮：标准流程
10. 一次标准技能创建流程是什么？答：新建技能、写 `SKILL.md`、补资源、保存、绑定到 Agent、做一次实际测试。
11. 导入单文件和导入目录有什么区别？答：单文件适合轻量技能，目录适合包含资源树的完整能力包。
12. 导出 markdown 和 zip 有什么区别？答：markdown 只带文本，zip 适合完整迁移。

### 第 5 轮：协作链路
13. Skills 最常和哪个模块配合？答：最常和 Agents 配合。
14. 为什么不直接把技能内容写进 Agent 提示词？答：因为这样难复用、难维护，也不利于来源管理。
15. 外部目录对团队有什么价值？答：它让多个工作区共享同一套技能源。

### 第 6 轮：进阶能力
16. 技能的高级价值是什么？答：把个人经验沉淀成可移植、可版本化的提示资产。
17. 为什么源目录规范化值得关注？答：因为 Claude Code 和其他 agent 目录有专门的路径归一化逻辑。
18. 什么时候技能会比新建 Agent 更划算？答：当变化的是领域知识，而不是角色和权限边界。

### 第 7 轮：结果判断
19. 什么算一个好技能？答：边界清楚、说明可执行、资源组织稳定、绑定到多个 Agent 后仍然一致。
20. 什么算技能写坏了？答：内容过长、约束冲突、资源散乱，导致 Agent 反而更不稳定。
21. 什么时候该拆成多个技能？答：当一份技能里混了不同领域或不同操作模式。

### 第 8 轮：常见故障
22. 技能绑定了但效果不明显怎么办？答：先查 Agent 是否真的启用该技能，再查技能内容是否足够具体。
23. 导入失败常见原因是什么？答：目录结构不规范、`SKILL.md` 解析失败或资源打包不完整。
24. 外部目录没加载到技能怎么办？答：先查目录是否启用，再查工作区设置是否已保存。

### 第 9 轮：安全边界
25. Skills 最大的风险是什么？答：把高风险脚本、模糊指令或不可信资源悄悄打包给 Agent。
26. 为什么“技能不是工具”这件事重要？答：因为你不能靠技能绕过真正的工具权限和安全策略。
27. 什么时候必须谨慎安装注册表技能？答：当技能来源不明、资源树复杂或包含脚本目录时。

### 第 10 轮：维护与迭代
28. 技能如何长期维护？答：按来源管理、定期导出备份、清理重复技能并复盘效果。
29. 什么时候该升级为共享目录？答：当技能已从个人尝试变成团队公共资产时。
30. 下一轮优化优先级是什么？答：先清理内容和边界，再补资源，再扩展来源管理。

## 7. Timer

如果你要看超细版样板，请继续阅读 [docs/user/TIMER_DEEP_DIVE_ZH.md](../user/TIMER_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Timer 解决什么问题？答：它负责按时间触发提醒、Agent Prompt 或已保存流水线。
2. 什么时候先打开 Timer？答：当流程不只要复用，还要按计划自动发生时。
3. 进入前最好准备什么？答：准备好要触发的 Agent 或流水线。

### 第 2 轮：首次配置
4. 第一次创建时先想什么？答：先想清楚是一次性、间隔还是 Cron 任务。
5. 新手先用哪一类最稳？答：先用 Once 或低频 Interval，确认动作逻辑正确后再上 Cron。
6. 为什么不建议一开始就高频执行？答：因为很容易快速放大模型成本和错误触发次数。

### 第 3 轮：核心对象
7. Timer 的核心对象有哪些？答：定时任务、调度类型、动作类型、启用状态、下一次执行时间和历史状态。
8. 动作类型有哪些？答：桌面通知、Agent Prompt、已保存流水线。
9. 为什么 Timer 要读取 Pipeline？答：因为它可以直接调度已保存流水线。

### 第 4 轮：标准流程
10. 标准创建流程是什么？答：命名、选调度类型、填时间规则、选动作、绑定 Agent 或 Pipeline、保存、启用、观察下一次运行时间。
11. Run now 有什么意义？答：它让你先验证动作链路，而不是盲等计划时间。
12. 什么时候要改时区和错过执行策略？答：当任务跨时区、机器会休眠，或你必须明确补跑/跳过行为时。

### 第 5 轮：协作链路
13. Timer 最常和哪些模块协作？答：Pipeline、Agents、Settings。
14. 什么任务适合直接 Prompt Agent？答：轻量提醒、短报告或单步问答。
15. 什么任务更适合先封装成 Pipeline？答：多步处理、依赖结构化输出或需要重试策略的任务。

### 第 6 轮：进阶能力
16. Timer 的进阶价值是什么？答：把手工触发的 AI 任务变成可观察、可复用的时间驱动流程。
17. AI Create 适合什么时候用？答：当你知道业务目标，但不想手填所有调度字段时。
18. 什么时候要显式配置重试？答：当动作依赖网络、provider 或外部平台时。

### 第 7 轮：结果判断
19. 什么算一个好定时器？答：触发时间明确、动作可验证、失败可重试，而且不会无意义地耗费模型额度。
20. 什么算“任务在跑，但对业务没价值”？答：输出没人看、时机不对或根本不需要自动化。
21. 什么时候应该拆成多个 Timer？答：当不同节奏、不同动作和不同时区混在一个任务里时。

### 第 8 轮：常见故障
22. 定时器不触发先查什么？答：先查是否启用、时间规则是否合法、下一次运行时间是否合理。
23. 触发了但没产出通常查什么？答：查绑定的 Agent、Pipeline、provider 和日志。
24. Cron 总出错通常为什么？答：表达式不正确，或你对时区和机器运行状态的预期不一致。

### 第 9 轮：安全边界
25. Timer 最大的风险是什么？答：把高权限 Agent 或高成本流程设成自动反复执行。
26. 为什么自动任务比手动任务更需要克制？答：因为错误会在无人值守时被持续放大。
27. 哪类动作最该先做 run now？答：所有会调用模型、工具或外部平台的动作都该先手动验证。

### 第 10 轮：维护与迭代
28. Timer 如何长期维护？答：定期清理失效任务、复盘失败记录、收敛重复计划。
29. 什么时候该停用任务而不是修修补补？答：当任务已经没有业务价值，或它的触发频率明显不合理时。
30. 下一轮优化优先级是什么？答：先稳调度，再稳动作，再优化失败策略。

## 8. Channels

如果你要看超细版样板，请继续阅读 [docs/user/CHANNELS_DEEP_DIVE_ZH.md](../user/CHANNELS_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Channels 解决什么问题？答：它把外部消息平台接入工作台，并把入站消息路由给指定 Agent。
2. 什么时候先打开 Channels？答：当你要让 Suora 不只在桌面里工作，而要接收外部消息时。
3. 进入前需要准备什么？答：准备平台凭据、回调或连接方式，以及负责回复的 Agent。

### 第 2 轮：首次配置
4. 第一次建渠道时先想什么？答：先想清楚目标平台、传输模式和回复 Agent。
5. 当前支持哪些平台？答：企业微信、个人微信、公众号、小程序、飞书、钉钉、Slack、Telegram、Discord、Teams、Email、自定义渠道。
6. Webhook 和 Stream 怎么选？答：能用 Stream 且不想暴露回调地址时优先 Stream，否则用 Webhook。

### 第 3 轮：核心对象
7. Channels 的核心对象有哪些？答：渠道配置、平台凭据、连接模式、回复 Agent、消息、用户、健康状态、调试记录。
8. 一个渠道绑定一个 Agent 有什么意义？答：这样每个消息入口的回复风格和权限边界更稳定。
9. `allowedChats` 的价值是什么？答：它能限制哪些群或会话允许触发自动处理。

### 第 4 轮：标准流程
10. 标准建渠道流程是什么？答：选平台、填凭据、选模式、绑 Agent、保存、启动服务或连流、发测试消息、看 Health 和 Debug。
11. 渠道详情页先看哪个标签？答：先看 Config，再看 Health，最后看 Debug。
12. 为什么消息历史也重要？答：它帮助你核对平台是否真的把消息送进来了。

### 第 5 轮：协作链路
13. Channels 最常和哪些模块协作？答：Models、Agents、Settings、Logs。
14. 为什么外部消息回复前一定要先稳住 Agent？答：因为渠道只是入口，真正输出质量和风险控制还是取决于 Agent。
15. Email 通道和聊天平台通道的差别是什么？答：Email 还包含 IMAP/SMTP、过滤规则和动作链配置。

### 第 6 轮：进阶能力
16. 渠道的高级价值是什么？答：把桌面工作台变成多入口运行面，而不是只能本地对话。
17. 个人微信当前的特殊点是什么？答：它支持二维码绑定后的桥接式能力与直接轮询/回复配置。
18. Email 通道可以做什么？答：可以轮询邮箱、按规则过滤邮件，并执行自动回复、转发、打标签、Agent 处理或 Webhook 动作。

### 第 7 轮：结果判断
19. 什么算渠道配置成功？答：平台能送入消息、Health 正常、Debug 没有持续错误，而且目标 Agent 能稳定回复。
20. 什么算只是“保存了渠道”但还没上线？答：服务没启动、凭据未验证、测试消息没跑通或自动回复没打开。
21. 什么时候该拆成多个渠道？答：当不同平台、不同会话群体或不同业务场景需要不同 Agent 和策略时。

### 第 8 轮：常见故障
22. 收不到消息先查什么？答：先查渠道是否启用、服务是否在线、平台回调或连接参数是否一致。
23. 能收不能回通常查什么？答：先查 reply Agent、平台凭据和模型侧可用性。
24. Email 不处理邮件通常为什么？答：常见原因是 IMAP/SMTP 字段、轮询间隔、过滤规则或动作链没有配置对。

### 第 9 轮：安全边界
25. Channels 最大的风险是什么？答：把自动回复、高权限 Agent 和开放消息入口直接连在一起。
26. 为什么白名单很重要？答：它能防止无关群或未知来源触发模型调用。
27. 哪类凭据最该谨慎管理？答：Webhook secret、Bot token、签名密钥、邮箱口令和桥接认证信息。

### 第 10 轮：维护与迭代
28. 渠道上线后如何维护？答：定期看 Health、Debug、消息量和失败模式，再决定是否旋转凭据或调 Agent。
29. 什么时候要先停用渠道？答：出现异常自动回复、凭据疑似泄露或调试面板持续报错时。
30. 下一轮优化优先级是什么？答：先稳传输，再稳 Agent，再扩展更多平台和自动化规则。

## 9. MCP

如果你要看超细版样板，请继续阅读 [docs/user/MCP_DEEP_DIVE_ZH.md](../user/MCP_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. MCP 解决什么问题？答：它把外部 MCP 服务接入 Suora，让 Agent 可以调用更多能力。
2. 什么时候先打开 MCP？答：当内置工具和普通技能已经不够，你需要外部系统能力时。
3. 进入前需要准备什么？答：准备服务器连接方式、命令、URL、环境变量或认证头信息。

### 第 2 轮：首次配置
4. 第一次添加服务器时先想什么？答：先想清楚它是工作区级还是用户级配置。
5. 当前支持哪些连接方式？答：`stdio`、`http`、`sse`、`ws`。
6. 新手先从哪类最稳？答：如果有成熟 URL 服务先用 `http` 或 `sse`，本地命令型服务再用 `stdio`。

### 第 3 轮：核心对象
7. MCP 的核心对象有哪些？答：服务器配置、传输方式、作用域、参数、环境变量、认证头、连接状态和暴露工具。
8. 作用域为什么重要？答：它决定配置是跟工作区走还是跟整个用户环境走。
9. 为什么要关心暴露工具列表？答：因为 Agent 真正可用的能力范围要靠它来判断。

### 第 4 轮：标准流程
10. 标准添加流程是什么？答：新建服务器、选传输方式、填命令或 URL、补环境变量或头、保存、测试连接、回到 Agent 使用。
11. 测试连接的意义是什么？答：先验证协议和地址，不要等到 Chat 里调用失败才回头排查。
12. 什么时候要填 headers 或 env？答：当远端服务或本地命令依赖认证和运行环境时。

### 第 5 轮：协作链路
13. MCP 最常和哪个模块协作？答：最常和 Agents、Chat、Settings 协作。
14. 为什么先配 MCP 再配 Agent 更稳？答：因为只有先确认服务真的可连，Agent 的工具边界才有意义。
15. 技能和 MCP 的区别是什么？答：技能提供提示和资源，MCP 提供真实外部能力接口。

### 第 6 轮：进阶能力
16. MCP 的进阶价值是什么？答：把 Suora 从本地工作台扩展成可调用外部服务的执行面。
17. `stdio` 适合什么？答：适合本机命令驱动的服务或开发期工具。
18. `ws` 和 `sse` 适合什么？答：适合需要持续连接或事件流的 MCP 服务。

### 第 7 轮：结果判断
19. 什么算 MCP 配置完成？答：服务器状态正常、可列出能力，并且 Agent 能在实际任务里调用到它。
20. 什么算只“保存了配置”但没真正接通？答：状态没通过、URL 或命令不对、Agent 也没真正使用到。
21. 什么时候该拆多个服务器？答：当能力域、安全等级或作用域完全不同的时候。

### 第 8 轮：常见故障
22. 连不上先查什么？答：先查协议、地址、命令、工作目录、环境变量和认证头。
23. URL 配好了还失败通常是什么原因？答：协议不被允许、服务没启动或网络不可达。
24. Agent 看不到 MCP 能力怎么办？答：先查服务器状态，再查 Agent 是否允许使用对应能力。

### 第 9 轮：安全边界
25. MCP 最大的风险是什么？答：把高权限外部能力直接暴露给宽权限 Agent。
26. 为什么作用域要谨慎选？答：因为用户级配置会影响更多工作区，出问题时影响面更大。
27. 哪类服务要最谨慎？答：能访问文件系统、执行命令、操作生产系统或持有长期密钥的服务。

### 第 10 轮：维护与迭代
28. MCP 配置如何长期维护？答：按服务域拆分、定期测试状态、清理失效端点和过期凭据。
29. 什么时候该先禁用服务？答：出现异常调用、权限边界不清或连接状态持续异常时。
30. 下一轮优化优先级是什么？答：先稳连接，再收权限，再扩能力面。

## 10. Settings

如果你要看超细版样板，请继续阅读 [docs/user/SETTINGS_DEEP_DIVE_ZH.md](../user/SETTINGS_DEEP_DIVE_ZH.md)。

### 第 1 轮：定位与入口
1. Settings 解决什么问题？答：它收口界面偏好、安全策略、数据管理、知识设置、事件自动化、插件、日志和系统状态。
2. 什么时候先打开 Settings？答：当你要控制全局行为，而不是某个单模块的局部效果时。
3. 当前有哪些分区？答：`general`、`security`、`voice`、`shortcuts`、`data`、`knowledge`、`events`、`external-dirs`、`plugins`、`logs`、`system`。

### 第 2 轮：首次配置
4. 第一次进来先看什么？答：先看 General 和 Security。
5. 为什么先看 General？答：这里决定主题、语言、工作区默认行为、代理和基础环境配置。
6. 为什么 Security 紧随其后？答：因为文件系统、工具确认和危险模式拦截会影响整个工作台的风险面。

### 第 3 轮：核心对象
7. Settings 的核心对象有哪些？答：主题与语言、工具安全、快捷键、数据导入导出、知识设置、事件自动化、外部目录、插件、日志和系统信息。
8. 为什么说 Settings 影响所有模块？答：因为 provider 密钥、工具权限、日志、数据路径和外部目录都在这里被统一控制。
9. 外部目录和 Skills/Agents 的关系是什么？答：它们是共享技能和 Agent 资源进入当前工作区的入口。

### 第 4 轮：标准流程
10. 一次标准设置检查怎么走？答：先 General，再 Security，再按任务需要看 Data、Logs、System 及其他分区。
11. 数据导出什么时候做？答：在大规模改 Agent、Skill、Pipeline 或迁移工作区前。
12. 日志面板最适合什么时候看？答：当某个模块现象奇怪，但你还没定位到根因时。

### 第 5 轮：协作链路
13. Settings 最常和哪些模块联动？答：几乎所有模块都联动，尤其是 Models、Skills、Agents、Channels、MCP。
14. 为什么外部目录会影响 Skills 和 Agents？答：因为它们会从这里加载共享目录资源。
15. 为什么 Logs 和 System 不是“最后才看”的摆设？答：很多问题只有在这里才能看到运行证据和系统状态。

### 第 6 轮：进阶能力
16. Settings 的高级价值是什么？答：它把工作台从“能跑”提升到“可控、可迁移、可诊断”。
17. Events 分区适合做什么？答：管理文件、剪贴板、启动等事件触发的自动化行为。
18. Knowledge 分区适合什么时候看？答：当你开始把文档和语义检索当长期知识系统来维护时。

### 第 7 轮：结果判断
19. 什么算设置合理？答：界面顺手、安全策略不过宽、日志可查、数据可导、扩展目录有序。
20. 什么算设置失控？答：权限过宽、目录混乱、密钥状态不清、日志没人看、导出从不做。
21. 什么时候该回收配置？答：当旧代理、旧目录、旧插件或旧自动化已经无人使用时。

### 第 8 轮：常见故障
22. 配置改了没生效先查什么？答：先查是否保存、是否是工作区级设置、是否受其他模块缓存影响。
23. 为什么模型密钥重启后消失？答：通常是 Secure Storage 不可用，当前行为只在内存中保留。
24. 外部目录没加载怎么办？答：先查路径、启用状态和工作区设置保存结果。

### 第 9 轮：安全边界
25. Settings 最大的风险是什么？答：在自己没意识到的情况下把全局权限和外部入口放得过宽。
26. 哪个分区最该谨慎？答：Security、External Directories、Plugins、Data。
27. 为什么日志也和安全相关？答：因为它是发现异常执行、失败链路和配置错误的证据面。

### 第 10 轮：维护与迭代
28. Settings 应该多久复盘？答：每当新增一类自动化、外部平台或共享目录后都该复盘一次。
29. 什么时候需要立刻做数据备份？答：在大改全局设置、迁移环境或导入大量配置前。
30. 下一轮优化优先级是什么？答：先稳安全，再稳数据，再扩自动化和扩展能力。
