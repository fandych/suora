# Suora Channels 深度迭代手册（30 个落地点）

这份手册把 `Channels` 模块收敛成 30 个真实落地点，重点是平台接入、传输模式、回复 Agent 和运维可见性。

## 1. 平台与模式

1. 先区分平台类型，再谈具体字段。
2. 先区分 webhook 和 stream，再做接入决策。
3. 个人微信与企业微信不要混作同一接入路径。
4. Email 通道比普通聊天平台更像工作流入口。
5. 自定义通道适合无法直接适配的内部网关。

## 2. 核心配置

6. 每个渠道应绑定一个明确的 reply Agent。
7. 渠道名称应反映平台和业务用途。
8. 凭据字段应按平台最小必需原则填写。
9. auto reply 开关上线前应先关闭测试。
10. allowed chats 应尽量收窄，而不是全放开。

## 3. 运行观察

11. Config 面板负责看静态配置。
12. Messages 面板负责看是否真的收到了流量。
13. Users 面板负责看谁在触发。
14. Health 面板负责看运行状态。
15. Debug 面板负责看失败证据。

## 4. 平台特性

16. 个人微信应重点关注绑定状态和二维码路径。
17. 钉钉应重点关注 stream 与 webhook 选择。
18. Slack/Telegram/Discord/Teams 应重点关注 token 与签名类字段。
19. Email 应重点关注 IMAP/SMTP、过滤规则和动作链。
20. Custom 应重点关注认证头和 payload 模板。

## 5. 安全与风险

21. 对外自动回复渠道优先绑定保守 Agent。
22. 生产环境优先从白名单小范围试点开始。
23. 平台密钥、邮箱口令和桥接认证都应视为高敏感配置。
24. Debug 里长期报错的渠道应优先停用而不是忽略。
25. 任何“能收不能回”的状态都应同时排查平台侧和模型侧。

## 6. 治理与维护

26. 高消息量渠道应定期看健康和延迟趋势。
27. 业务边界变化时应重新审查 reply Agent。
28. 无人维护的测试渠道应及时清理。
29. Email 规则过多时应做规则收敛。
30. 好的 Channels 治理最终目标是接入稳定、回复可控、证据可查、边界清楚。
