# Suora Agents 深度迭代手册（30 个落地点）

这份手册把 `Agents` 模块收敛成 30 个真实落地点，重点是角色、提示词、权限、记忆和复用边界。

## 1. 角色定位

1. 把 Agent 理解为执行单元，而不是提示词模板。
2. 先定义角色，再调模型。
3. 先定义边界，再扩功能。
4. 通用 Agent 和专业 Agent 的职责应分开。
5. 构建器 Agent 不应替代业务 Agent。

## 2. 提示词设计

6. 系统提示词应先写目标，再写边界。
7. 提示词应避免把多个冲突角色混在一起。
8. 格式要求应显式写出。
9. 风险限制应显式写出。
10. 不确定性处理应显式写出。

## 3. 配置要素

11. 模型绑定应服务任务类型。
12. 技能绑定应服务领域稳定性。
13. max turns 应控制对话扩张。
14. 温度和 token 上限应服务输出预期。
15. response style 应与交付场景匹配。

## 4. 权限与记忆

16. allowed tools 只给真正需要的工具。
17. disallowed tools 适合收紧高风险面。
18. permission mode 不应长期保持过宽。
19. memories 只在确实有长期复用价值时打开。
20. autoLearn 不应替代人工治理。

## 5. 测试与演进

21. 大改提示词前先做版本快照。
22. 新 Agent 应先在模块内测试，再进真实工作流。
23. 复制已有 Agent 常比从零新建更稳。
24. 一个 Agent 同时承担两种风格冲突职责时应拆分。
25. 长期无人用的 Agent 应清理或归档。

## 6. 协作与治理

26. Chat 暴露角色问题时应回到 Agents 修，而不是一直追问。
27. Pipeline 步骤越关键，Agent 边界越应清楚。
28. Channels 绑定的 Agent 应比聊天试玩 Agent 更保守。
29. 高价值角色规则可转为 Skill 复用。
30. 好的 Agent 治理最终目标是职责清楚、输出稳定、权限可控、版本可回退。
