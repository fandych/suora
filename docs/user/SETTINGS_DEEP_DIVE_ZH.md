# Suora Settings 深度迭代手册（30 个落地点）

这份手册把 `Settings` 模块收敛成 30 个真实落地点，重点是全局控制面、安全边界、数据治理和诊断能力。

## 1. 全局控制面

1. Settings 影响的是整个工作台，而不是单个页面。
2. General 负责主题、语言和基础偏好。
3. Security 负责高风险边界。
4. Data 负责导入、导出、清理和备份。
5. Logs/System 负责诊断和系统可见性。

## 2. 安全配置

6. Secure Storage 提示必须被看见并理解。
7. 工具确认策略应与风险等级匹配。
8. allowlist 目录应尽量最小化。
9. 危险 shell 模式拦截应默认保守。
10. 高权限设置不应长期为调试方便而放开。

## 3. 数据与扩展

11. Data 导出应在大改前执行。
12. 外部目录应区分 Agents 和 Skills 两类来源。
13. 共享目录应定期检查是否仍被使用。
14. Plugins 应按信任级别管理。
15. 环境变量和代理配置应保持可解释而不是堆积。

## 4. 知识与自动化

16. Knowledge 设置服务的是长期知识工作流。
17. Events 设置服务的是非对话触发式自动化。
18. Voice 和 Shortcuts 属于效率配置，而不是核心业务逻辑。
19. 自动化越多，越应定期回看 Settings。
20. 新增外部能力后应先复查安全分区。

## 5. 诊断与恢复

21. 某模块行为怪异时，先想 Logs/System 能否提供证据。
22. 配置改了没生效时先查作用域和保存路径。
23. 密钥重启后丢失时先回看 Secure Storage 状态。
24. 外部目录加载异常时先查启用状态与路径。
25. 故障恢复应先定位到对应分区，而不是盲改全局配置。

## 6. 治理与维护

26. 不再使用的共享目录应及时移除。
27. 长期闲置插件应停用或卸载。
28. 高价值工作区应建立固定备份节奏。
29. 每次新增自动化和外部平台后都应做一次全局复查。
30. 好的 Settings 治理最终目标是偏好清楚、安全收敛、数据可回退、诊断可执行。
