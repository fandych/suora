# Suora Documents Deep Dive (30 Concrete Iteration Points)

This guide expands the `Documents` module into 30 concrete iteration points focused on knowledge structure, backlinks, graph health, and long-term reuse.

## 1. Why Documents matters

1. Treat Documents as the local knowledge layer, not a temporary scratchpad.
2. Use Documents when information should outlive a single chat thread.
3. Prefer Documents when material will be reused across tasks.
4. Prefer Documents when note relationships matter.
5. Prefer Documents when search and graph visibility matter.

## 2. Group and folder design

6. Create document groups around real boundaries such as project, domain, or audience.
7. Keep top-level groups small and clear.
8. Split overloaded groups before they become search junk drawers.
9. Use folders to express primary hierarchy, not every possible relationship.
10. Keep tree depth useful but not excessive.

## 3. Writing and structure

11. Keep one document centered on one core question when possible.
12. Use titles that explain why the note exists.
13. Put purpose or conclusion near the top.
14. Use headings to make long notes scannable.
15. Use Mermaid and math only when they clarify the content.

## 4. Links, search, and graph

16. Link notes when the relationship reduces reader guesswork.
17. Use backlinks to see who depends on a note.
18. Treat isolated notes as review candidates, not always as errors.
19. Use consistent terms so search can work reliably.
20. Use graph view to reveal bridges, sparse clusters, and missing index pages.

## 5. Collaboration with the rest of the workbench

21. Move durable chat output into Documents when it should become reusable knowledge.
22. Inject only the most relevant documents into Chat.
23. Use Document editor style agents when the result must be saved, not only discussed.
24. Let Documents provide stable context for specialist agents.
25. Use Documents as the knowledge anchor for later pipelines.

## 6. Governance and safety

26. Review imports before letting source structure define your knowledge structure.
27. Export backups before major structural rewrites.
28. Clean up duplicates regularly.
29. Review sensitive notes before exporting or injecting them into other workflows.
30. A healthy Documents system should be findable, linkable, maintainable, and reusable.
