# Suora Timer 深度迭代手册（30 个落地点）

这份手册把 `Timer` 模块收敛成 30 个真实落地点，重点是调度策略、动作选择、无人值守风险和维护节奏。

## 1. 调度类型

1. Once 适合单次提醒或一次性自动执行。
2. Interval 适合固定节奏的轻量任务。
3. Cron 适合明确时点规则的长期任务。
4. 新手应先用 Once 或低频 Interval。
5. 高频任务应先确认业务价值，再考虑启用。

## 2. 动作选择

6. 通知动作适合纯提醒。
7. Agent Prompt 适合单步 AI 任务。
8. Pipeline 动作适合多步自动化。
9. 不要用 Prompt 动作硬扛本该是 Pipeline 的复杂流程。
10. Pipeline 动作上线前必须先手动跑通。

## 3. 运行策略

11. Run now 是上线前的第一验证手段。
12. next run 显示异常时先停用再排查。
13. timezone 不清楚时不要盲上 Cron。
14. missed-run policy 应与业务容忍度匹配。
15. retry 策略只给真正有瞬时失败可能的任务。

## 4. 风险控制

16. 无人值守任务优先使用窄权限 Agent。
17. 高成本模型不应绑定到高频任务上。
18. 涉及外部系统的定时任务应先审查副作用。
19. 定时自动化越复杂，越应先抽成 Pipeline。
20. 异常触发时应优先停用任务而不是硬撑运行。

## 5. 协作与排障

21. Timer 与 Pipeline 的结合点在可复用多步流程。
22. Timer 与 Agents 的结合点在轻量定时 Prompt。
23. Timer 异常先看绑定对象是否仍可用。
24. 任务触发但无结果时优先查日志和模型可用性。
25. 长期不再使用的定时任务应及时清理。

## 6. 治理与维护

26. 名称应包含触发意图而不是只写“定时任务”。
27. 高价值任务应记录验证方法。
28. 任务变复杂时应回头重构，而不是不断叠补丁。
29. 重要任务在大改前应先做配置备份。
30. 好的 Timer 治理最终目标是调度清楚、动作稳定、风险可控、失败可恢复。
