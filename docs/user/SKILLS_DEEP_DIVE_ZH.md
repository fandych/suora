# Suora Skills 深度迭代手册（30 个落地点）

这份手册把 `Skills` 模块收敛成 30 个真实落地点，重点是 `SKILL.md`、来源、资源树、共享和安全审查。

## 1. 基础认知

1. Skill 是提示与资源包，不是工具实现。
2. `SKILL.md` 是技能核心，不是附件说明。
3. 技能解决的是复用领域规则问题。
4. Agent 解决的是角色问题。
5. 不要用 Skill 去绕过权限系统。

## 2. 内容组织

6. Skill 名称应清楚说明用途。
7. 适用场景应显式写明。
8. 输入要求应显式写明。
9. 输出要求应显式写明。
10. 限制与禁止项应显式写明。

## 3. 资源树与来源

11. 资源树适合承载模板、参考和补充资产。
12. `scripts/` 目录资源要额外谨慎。
13. 本地、项目、用户、注册表来源应分开理解。
14. 外部目录适合团队共享能力库。
15. 导入目录和导入单文件适合不同复杂度场景。

## 4. 绑定与复用

16. 同一 Skill 适合绑定到多个角色相近的 Agent。
17. Agent 总是不稳定时，应检查 Skill 是否写得过宽。
18. 角色变了但领域规则未变时，应优先改 Agent 而不是 Skill。
19. 多个 Skill 边界重叠时，应先拆清职责。
20. 无人使用的 Skill 应清理或归档。

## 5. 安全与审查

21. 安装注册表 Skill 前先看来源可信度。
22. 资源里含脚本时先做人工审查。
23. 不要把敏感密钥直接写进 Skill 内容。
24. 不要把高风险操作说成默认流程。
25. 技能越强，边界越要写清楚。

## 6. 治理与维护

26. 高价值 Skill 应导出备份。
27. 长期复用的 Skill 应升级到共享目录治理。
28. 中英文团队若共用能力，应统一术语和结构。
29. Skill 文案与资源树都应定期复盘。
30. 好的 Skills 治理最终目标是边界清楚、来源可追、资源可管、复用稳定。
