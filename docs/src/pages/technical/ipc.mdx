# IPC 通信

SUORA 使用 Electron IPC 连接 React Renderer 与主进程。Renderer 不直接访问 Node.js、文件系统、网络或 SQLite；它通过 preload 暴露的受控 bridge 请求主进程能力。

## 调用链

典型调用链如下：

```text
React page / store
  → src/services/<module>-service.ts
  → window.app.<domain>.<method>
  → ipcRenderer.invoke(channel, payload)
  → ipcMain.handle(channel, handler)
  → electron/app/<domain>/service.ts
  → repository / runtime / infrastructure
  → serialized result
```

页面通常不直接调用 `ipcRenderer`。更推荐的层次是：

1. 页面只处理交互、加载与展示
2. `src/services/` 封装 bridge 调用、事件订阅与 renderer 侧数据转换
3. preload 提供最小化、按业务域组织的方法
4. 主进程 handler 负责权限、边界与输入校验

## `window.app` 与 `window.electron`

当前 preload 暴露两类入口：

### `window.app`

这是日常业务调用的主入口，按业务域提供方法，例如：

- `system`
- `workspace`
- `chats`
- `documents`
- `models`
- `skills`
- `agents`
- `integrations`
- `workflows`
- `channels`
- `schedulers`
- `preferences`
- `updater`
- `mail`
- `tools`

Renderer 中的大多数业务代码都应先经 `src/services/` 调用 `window.app`。

### `window.electron`

这是一个白名单化的低层入口，只允许少数显式通道：

- invoke：`ai:fetch:start`、`ai:fetch:abort`、`integration:execute`、`channel:wechatPersonalQrPreview`
- event：`ai:fetch:event`、`channel:message`、`workflow:run:event`、`tools:browserStateChanged`

它不是任意 IPC 代理。除非能力天然是流式事件或受控低层调用，否则优先使用 `window.app`。

## IPC 注册

IPC 注册入口位于 [src/electron/preload/index.ts](C:/Users/fandych/Documents/Codespace/suora/src/electron/preload/index.ts)。主进程启动时调用 `setupIpc()`，按业务域注册 handler：

- `electron/preload/system/`
- `electron/preload/chats/`
- `electron/preload/documents/`
- `electron/preload/models/`
- `electron/preload/skills/`
- `electron/preload/agents/`
- `electron/preload/integrations/`
- `electron/preload/workflows/`
- `electron/preload/channels/`
- `electron/preload/schedulers/`
- `electron/preload/preferences/`
- `electron/preload/tools/`

新增 IPC 能力时，应同时修改：

1. 对应领域的 `*-ipc.ts`
2. `preload.ts` 中暴露的 bridge 方法
3. 相关 `src/types/` 契约
4. renderer 侧 `src/services/` 封装

不要只在页面里新增一个裸 `ipcRenderer.invoke(...)` 调用。

## 输入与输出约束

IPC handler 接收到的所有 payload 都应视为不可信输入。典型约束包括：

- ID、路径、URL、邮箱、JSON payload 的运行时校验
- 文件大小、消息大小、分页数量和超时边界
- 资源可见性与权限范围检查
- 仅返回可序列化数据，不返回主进程对象引用

TypeScript 类型只解决编译期契约，不能替代主进程运行时验证。

## 事件与流式数据

部分能力通过事件而不是一次性 Promise 返回：

- AI 流式生成与工具事件：`ai:fetch:event`
- workflow 后台运行事件：`workflow:run:event`
- 渠道入站消息：`channel:message`
- 隐藏浏览器状态更新：`tools:browserStateChanged`

订阅事件的 renderer 代码必须在组件卸载或作用域结束时取消订阅，避免重复监听和内存泄漏。

## 数据库边界

当前 Renderer 不提供通用 `db:execute` SQL bridge，也不应从页面直接拼接 SQL。数据库访问应通过主进程领域 service 和 repository 完成，例如：

- `window.app.chats.*`
- `window.app.documents.*`
- `window.app.models.*`
- `window.app.workflows.*`

如果某个功能需要新查询，优先在对应业务域的 main-process service/repository 中新增能力，再通过 preload 暴露受控接口。

## 安全边界

- BrowserWindow 使用 `contextIsolation: true`
- 主窗口关闭 `nodeIntegration`
- preload 不暴露完整 `ipcRenderer`
- 主进程重新校验路径、命令、URL、凭据与资源权限
- Renderer 不能借由 prompt、网页内容或 Skill 内容提升 IPC 权限

IPC 隔离并不等于多租户权限系统；当前仍是本地桌面应用，最终安全性依赖当前操作系统用户与本地数据保护。

## 错误处理建议

调用方应区分：

- **参数校验失败**：修正表单、payload 或资源选择后重试
- **权限/策略拒绝**：检查 Agent 绑定、Preferences 或 URL 范围
- **外部依赖失败**：检查 Provider、网络、代理、TLS 与目标服务状态
- **持久化失败**：检查 migration、磁盘可写性和工作区权限

错误信息应可被 UI 呈现，但不要包含 API Key、密码、Cookie、完整授权 header 或其他敏感字段。

## 修改 IPC 的检查清单

1. 确定能力属于哪个业务域
2. 在主进程 handler 中加入运行时校验
3. 在 `preload.ts` 暴露最小化 bridge 方法
4. 将跨进程契约写入 `src/types/`
5. 在 `src/services/` 中集中封装 renderer 调用
6. 覆盖拒绝路径、无权限资源、超时和外部失败
7. 在实际 Electron 运行时验证 bridge 是否可用
8. 运行 `npm run type-check`、`npm run lint`、`npm run test:run`、`npm run build`
