自动版本管理规则
1. 版本号格式

系统自动维护版本号，用户无需手动输入。

格式：

Major.Minor


例如：

1.0
1.1
1.2
2.0
2.1
2.2
...
m.n


其中：

Major：发布（Release）版本号
Minor：当前发布版本后的编辑次数
2. 创建与修改规则
新建

首次创建：

1.0

保存

每次保存自动递增 Minor：

1.0
↓ 保存
1.1
↓ 保存
1.2
↓ 保存
1.3
...
1.n

发布（Release）

当用户发布当前版本：

1.2 (Release)


此版本成为当前正式版本。

发布后的修改

后续继续编辑时：

系统自动基于最近一次 Release 创建下一主版本：

1.2 (Release)
↓ 编辑
2.0
↓ 保存
2.1
↓ 保存
2.2
...
2.n


再次发布：

2.4 (Release)


继续编辑：

3.0
3.1
3.2
...

3. 版本演进示例
1.0
1.1
1.2 (Release)

2.0
2.1
2.2
2.3
2.4 (Release)

3.0
3.1
3.2 (Release)

4.0
4.1
...

版本展示规则
显示原则

系统仅保留：

所有 Release 版本
当前开发链路上的临时版本

历史 Release 之前的临时版本自动隐藏。

示例 1

发布到：

1.2 (Release)


显示：

1.2 (Release)

2.0
2.1
2.2
2.3
2.4


隐藏：

1.0
1.1

示例 2

发布到：

3.2 (Release)


显示：

1.2 (Release)

2.4 (Release)

3.0
3.1
3.2 (Release)


隐藏：

1.0
1.1

2.0
2.1
2.2
2.3

最终展示效果
1.2 (Release)

2.4 (Release)

3.0
3.1
3.2 (Release)


仅保留：

历史正式发布版本
当前正在开发的版本链路
Dropdown 展示规则

版本选择器（Dropdown Menu）采用倒序排列：

3.2 (Release)
3.1
3.0

2.4 (Release)

1.2 (Release)


最新版本始终展示在最上方。

排序规则：

ORDER BY Major DESC, Minor DESC

Agent 绑定规则
绑定方式

Agent、Workflow、Knowledge Base 等关联关系不绑定具体版本号，而是绑定资源 ID。

例如：

KB-10001


而不是：

KB-10001@v1.0

运行时解析

系统执行时自动选择：

最新 Release 版本
+
当前开发版本（若存在）


例如：

当前版本情况：

1.2 (Release)

2.0
2.1
2.2
2.3


Agent 原来绑定：

KnowledgeBase = KB-10001


运行时自动解析为：

KB-10001@2.3


无需重新配置 Agent。

发布后自动切换

版本演进：

1.2 (Release)

2.0
2.1
2.2
2.3


发布：

2.4 (Release)


运行时自动变为：

KB-10001@2.4


Agent 配置保持不变。



这样既能保留所有正式发布版本，又能让 Agent 始终自动跟随最新版本，无需用户维护版本号或重新绑定。
