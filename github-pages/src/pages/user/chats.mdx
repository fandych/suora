# Chats

Chats 是 SUORA 的日常对话入口。可在此选择模型或 Agent、添加附件、观察流式回复与工具调用，并将完整转录导出为文件。

## 开始一个会话

1. 进入 **Chats** 并选择 **New chat**。
2. 在输入框上方选择模型；如需使用预设 instructions 和授权资源，再选择 Agent。
3. 输入问题，必要时添加附件，然后发送。

新建会话在发送第一段内容或附件前只是草稿，不会写入本地记录。首次发送后，SUORA 会创建真实会话；标题通常取首条用户消息的前 18 个字符。只有附件时，标题为 `Untitled chat`。

历史会话按最近更新时间排列。可在侧边栏选择会话；删除前会显示确认提示，删除后无法恢复，并会一同删除全部消息。Channels 写入的外部会话会保留在本地 Chat 中，但不会显示在普通 Chats 列表。

<Callout>
  目前 Chats 没有手动重命名会话的界面。若需要清晰的标题，请在首条消息中写出简短、明确的任务名称。
</Callout>

## 选择模型与 Agent

模型菜单按 Provider 分组显示已启用模型。若当前模型失效，应用会回退至第一个可用模型并提示 **Model unavailable**。

选择 Agent 后，实际生成优先使用 Agent 自己配置的 Provider、模型与最大步骤数；如果 Agent 未设置有效模型，则使用当前 Composer 的模型。Agent 同时会带入其 instructions，以及已经授权的 Documents、Skills、Workflows 和 Integrations。

建议先在 **Models** 中确认 Provider、Base URL、API Key 和模型已启用，再开始 Chats。遇到复杂任务时，使用目标明确、权限最小化的 Agent。

## 流式回复与停止

发送后，回复会以流式形式显示。回复中出现工具调用时，可查看其进行中、成功、失败或已停止的状态，并展开检查 JSON 输入、输出或错误信息。

生成期间可使用 **Stop**：

- 它会取消正在进行的模型请求；
- 已可见的文本和工具信息会尽量保留到会话；
- 中止后，本次待发送的附件会被清空。

目前没有“重新生成整条回复”的功能，但每个工具活动可单独重试；成功或失败结果会更新到该助手消息中。

## 添加附件

附件按钮仅会在当前模型具备 `vision` 能力时显示。支持：

- 图片：`image/*`
- 文本：`text/*`
- PDF：`application/pdf`
- JSON：`application/json`

限制如下：

| 项目 | 限制 |
| --- | --- |
| 单个文件 | 10 MiB |
| 单次最多文件数 | 5 个 |
| 单次附件总量 | 25 MiB |

应用会根据文件名称、大小、修改时间和 MIME 类型去重。若无法添加附件，请确认模型支持 vision、文件类型受支持且未超出限制。

<Callout type="warning">
  附件会成为会话消息的一部分并发送给当前模型服务。不要上传 API Key、密码、私钥或其他不应离开设备的敏感内容。
</Callout>

## 语音输入

输入框右侧的麦克风按钮可将语音识别结果追加到当前草稿。首次使用时，系统会请求麦克风权限；再次点击可停止录音。

- 此功能依赖运行环境提供 Web Speech Recognition；按钮不可用或提示 unavailable 时，请改用文本输入。
- 正在生成回复时，语音输入不可用。
- 识别语言默认跟随系统/浏览器语言；识别结果应在发送前人工核对。

## 导出会话

在会话页面使用导出操作，可将当前转录保存为：

- Markdown
- PDF
- DOCX

导出包含用户和助手文本、附件摘要以及工具调用、结果和错误。没有可导出内容或正在生成回复时，导出操作不可用。桌面应用会打开系统保存对话框；在无桌面 bridge 的环境中会退回浏览器下载。

### 导出单条消息

每条含文本的已完成消息均提供独立导出菜单，可单独保存为 Markdown、PDF 或 DOCX。适合仅分享某个回答，而不导出整个会话；消息操作区也提供复制和朗读功能。

## 对话记忆与保存

会话、消息、附件摘要和工具活动保存在本地 SQLite 工作区。会话运行设置（模型、Agent、代理、请求超时和最大步骤数）也会保存；未发送的输入内容不会保留，重新打开或切换会话时输入框会清空。

为控制上下文体积，模型直接接收最近 16 条消息。更早内容会压缩为 session memory，因此长会话中的细节可能被摘要。需要保持精确上下文时，建议拆分主题创建新会话，或将关键结论重新贴入当前对话。

## 常见问题

### 无法发送或提示 Desktop runtime required

Chats 发送请求依赖 Electron 的 IPC bridge。请从桌面应用启动，而不是仅在普通浏览器中打开渲染页面。

### 出现 Request failed、Request timed out 或 Response failed

确认模型仍已启用；检查 Provider 的 Base URL、API Key、网络、代理和请求超时设置。`ECONNREFUSED`、`ECONNRESET` 或 `fetch failed` 通常表示本地网络或模型服务连接问题。

### 出现 Step limit reached

Agent 在工具调用步骤达到预算前没有完成任务。缩小任务范围、减少所需工具，或在 Agent/Chats 设置中提高最大步骤数后重试。

### 出现 Operation blocked 或 Tool execution failed

检查 Agent 是否获得所需 Documents、Skills、Workflows 或 Integrations 授权；同时检查 Preferences 的文件访问、命令允许列表和确认策略。对于不可逆浏览器操作、登录、付款或账户变更，应先明确确认操作范围。
